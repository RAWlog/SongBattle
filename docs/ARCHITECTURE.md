# Архитектура проекта

Проект "Music Tournament" построен на современном стеке **Next.js 15 (App Router)** с использованием Server Components и Server Actions.

## Основные слои

### 1. Presentation Layer (UI)
*   **Технологии:** React, Tailwind CSS (v4), Shadcn UI.
*   **Ответственность:** Отображение пользовательского интерфейса, анимации переходов между матчами, отправка событий голосования.
*   **Архитектура:** Использование Server Components по умолчанию. Интерактивные элементы (клиентские компоненты) выделены в отдельные файлы (`MatchView.tsx`, `CreateTournamentForm.tsx`) и используют директиву `"use client"`.

### 2. Application Layer (Server Actions)
*   **Технологии:** Next.js Server Actions (`src/app/actions`).
*   **Ответственность:** Обработка пользовательского ввода (импорт плейлиста, голосование), вызов бизнес-логики, валидация.
*   **Примечание:** Роуты `api/` не используются. Все мутации данных происходят через строгие серверные действия для защиты от подделки запросов (CSRF) и избыточных сетевых вызовов.

### 3. Domain & Service Layer
*   **Расположение:** `src/services/`.
*   **Ответственность:** Чистая бизнес-логика, не привязанная к HTTP-контексту.
*   **Компоненты:**
    *   `bracket.service.ts`: Математика турнирной сетки.
    *   `elo.service.ts`: Расчет рейтингов Эло.
    *   `spotify.service.ts`: Скрейпинг HTML-виджетов.
    *   `youtube.service.ts`: JIT поиск видео.

### 4. Data Access Layer
*   **Технологии:** Prisma ORM, SQLite.
*   **Ответственность:** Обеспечение целостности данных, использование транзакций для обновления матчей и рейтингов треков в рамках одного голосования.
